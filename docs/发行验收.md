# 发行验收与实验交付资格

本文件说明验收范围和复核入口；测试数量、执行时间及退出状态以本发行目录的[verification_report.json](verification_report.json)和[extraction_verification.json](extraction_verification.json)为准，不在说明文字中固定旧数字。前者记录测试及失败项，后者记录ZIP解压后的入口与运行检查。原包遍历和法源核验分别有来源清单及[law_verification.md](law_verification.md)。

## 初始源码交付

初始交付提供完整运行工程、冻结前预注册输入及离线参考／弱路径记录。离线用于验证程序、权限、证据、分页、预算、恢复、无罪分支、评分和导出机制；mock裁决不能证明真实结局区分，离线机械得分不能替代60项双评分法律总分。实际离线得分直接查看各题`scores/`，不复制旧版本数字。

可在解压根目录重复检查：

```bash
bash setup.sh
bash run_005.sh offline
bash run_006.sh offline
bash run_005.sh status
bash run_006.sh status
python3 tools/verify_legal_sources_v2.py
```

这些命令不需要真实API密钥；实时接口预检与正式流水线会使用密钥并产生用量。源码包不是已完成实验结果包，初始缺少live记录时，严格`validate`／`export`拒绝验收是预期行为。

## 正式结果验收

每题自动流水线依次完成真实预检、参考／弱路径及其双评分、校准门禁与冻结、GPT两场和Seed两场及各自双评分，随后严格导出。验收包括：

- 预注册内容与冻结内容一致，真实校准证据及其哈希有效。
- 本题四场正式候选为live且完成，所需双评分齐全，模型及effort符合固定配置。
- 原始事件链、状态、工作文件不可变版本与哈希一致；没有未结调用标记。
- 机械评分重新计算一致，质量项及N/A覆盖正确，分母、罚分、均值、一致率与分歧算术一致。
- 逐罪无罪裁定及终局一致；依法提前终结与剩余罪名陪审票相容。
- 真实调用记录、用量及未知预留可追溯，未超每场／每题额度。
- 保留完整运行依赖和真实材料；拒绝越界路径、符号链接与疑似密钥泄露，生成逐文件SHA256并检查ZIP内容。

```bash
bash run_005.sh report
bash run_006.sh report
bash run_005.sh validate
bash run_006.sh validate
bash run_005.sh export
bash run_006.sh export
bash run_006.sh export-all
```

`export-all`需要当前工程中两题均满足正式资格。单题导出保留共享工程及另一题的静态依赖模板；模板不含另一题真实结果，也未作为该题正式结果验收。`DELIVERY.md`及`DELIVERY_MANIFEST.json`列明结果题目、模板题目、状态与文件哈希。

严格通过标为`verified_final_records`；显式`--allow-partial`标为`partial_not_final`，不能充作正式交付。当前完成数、分数、用量和冻结状态查看各题动态`RESULTS.md`、`进度.md`及`status`，不会由本文件硬编码。

## 验收的边界

自动检查核验工程行为及记录、评分一致性，不能保证模型必然取得高分、校准必然通过或服务商永不故障。失败时保留真实记录，修复原因后按恢复流程继续；不得生成缺失的候选工作文件或把失败当成成功。

历史关键核心已补核，但未复原完整历史法典／模式指示册，未完成执业律师全面人工法律审核；详细边界以[law_verification.md](law_verification.md)为准。教师没有OS镜像和完整依赖锁，环境对齐以`ENVIRONMENT.json`及固定模型／协议／预算为证，不承诺操作系统逐位一致。
